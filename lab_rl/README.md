# Лаба 3 (RL): Connect-4 — AlphaZero-lite против DQN, оценка по идеальному солверу

Агент учится играть в «Четыре в ряд» (7 × 6) **только из самоигры** и сравнивается с идеальным игроком.
Два подхода:

* **DQN** (негамакс, double DQN, ε-greedy self-play);
* **AlphaZero-lite**: сеть с головами политики и значения + **собственный векторизованный MCTS** (PUCT):
  256 деревьев в плотных numpy-массивах, все партии делают симуляцию одновременно, листья оценивает один вызов сети.

Ключевая идея оценки: Connect-4 **решена**, поэтому качество измеряется не «играет лучше слабого соперника», а
**точностью ходов против солвера Паскаля Понса** (C++, собирается из пиннутого коммита внутри контейнера) на двух наборах
размеченных позиций (`random` и `expert`) и **турниром с рейтингом Elo** (random, greedy, minimax, UCT, DQN, AZ с разным поиском,
идеальный игрок). Доверительные интервалы — bootstrap по позициям / партиям.

## Запуск (всё внутри контейнера)

```bash
cd lab_rl
docker compose run --rm eda        # анализ игры (CPU, пара минут)          -> outputs/eda.html
docker compose run --rm smoke      # крошечный сквозной прогон              -> outputs/smoke/report.html
docker compose run --rm lab        # полный эксперимент на GPU (~50 мин)    -> outputs/report.html
docker compose run --rm lab-cpu    # то же на CPU (медленнее)
docker compose up play-web         # сыграть с ботом в браузере             -> http://localhost:8000
docker compose run --rm play       # то же в терминале
docker compose run --rm test       # ruff + mypy --strict + pytest
```

Что скачивается/собирается в контейнере: исходники солвера (GitHub, при сборке образа, коммит
`d6ba50d8…`), дебютная книга солвера (32 МБ, при первом обращении к солверу, кладётся в `./cache`). Данных нет — их порождает самоигра.
Папки `./outputs` (отчёты, рисунки, чекпоинты), `./cache` и `./weights` монтируются с хоста. Без Docker проект тоже запустится:
если `c4solver` не найден, код сам клонирует и собирает его в `cache/solver` (нужны `git`, `g++`, `make`).

## Сыграть с ботом

Обученные веса лежат в репозитории (`weights/`, ~9 МБ), поэтому играть можно сразу, без обучения: AlphaZero-lite на 0%, 25%, 50% и
100% обучения, вариант со слабым поиском в self-play и DQN. В веб-интерфейсе можно выбрать:

* соперника — нейросеть (рядом указан её Elo из турнира отчёта) или классический бот: random, greedy, minimax, идеальный солвер;
* силу поиска MCTS (0–400 симуляций; 0 — чистая политика сети), свою сторону (X ходит первым);
* «мысли» бота: политика сети, доли визитов MCTS, оценка позиции;
* вердикты идеального солвера на каждый ваш ход (оптимален или ухудшил результат, какие колонки были лучше);
* отмену хода и новую партию.

Новые чекпоинты из `outputs/checkpoints` (после собственного прогона `lab`) подхватываются автоматически;
`python -m c4rl export-weights` копирует выбранные в `weights/` вместе с Elo из `outputs/results.pkl`.
Сервер — стандартная библиотека Python (`http.server`), веса считаются на CPU внутри контейнера, браузеру достаточно показывать доску.
При первом вердикте солвера скачивается дебютная книга (32 МБ) — первый ход может занять пару минут.

## Что в отчёте

1. Постановка и сравнение методов.
2. **EDA игры**: рост пространства состояний (полный перебор позиций до глубины 9), случайная игра, точные значения первых ходов,
   состав тестовых наборов (доля «нетривиальных» позиций, число оптимальных ходов).
3. Методы, формы тензоров, гиперпараметры.
4. Результаты: кривые обучения (по партиям и по времени), точность и грубые ошибки против солвера, зависимость от бюджета поиска,
   турнир и Elo, рост рейтинга по контрольным точкам, анализ value-головы, примеры позиций, **листалка партий** (JS внутри HTML).
5. Выводы: формулировки строятся из чисел запуска (значимо/не значимо по интервалам) + честный список ограничений.

## Профили

`smoke` (минуты, мелкие сети — только проверка конвейера), `standard` (основной отчёт), `full` (больше партий/симуляций).
Конфигурации в `src/c4rl/config.py`.

## Что важно помнить при интерпретации

* Один seed на прогон: интервалы описывают конечность тестовых позиций и турнирных партий, но не разброс между запусками обучения.
* «Одинаковое число партий» ≠ «одинаковые вычисления»: AZ тратит симуляции на каждый ход — отчёт показывает кривые и по времени.
* Солвер используется в «слабом» режиме (выигрыш/ничья/проигрыш), поэтому «оптимальный ход» = ход, не ухудшающий теоретический результат.
